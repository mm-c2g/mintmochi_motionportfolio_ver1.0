# 04. 現状の style.css とデザインシステム（01〜03）の差分・作業指示書

学習②（2026-09-27 実行分）。学習①が作った `01_typography.md` / `02_spacing-layout.md` /
`03_color-motion.md` と、実際の `style.css`（1173行）を1行ずつ突き合わせた結果。

**このファイル自体はコード改善担当への作業指示書。** そのまま手を動かせる粒度で書いてある。
`style.css` はこのセッションでも1文字も変更していない。

---

## 結論（先に）

- 一番インパクトが大きいのは **「固定remフォントサイズ」が11段階に散らばっている**こと（第1章）。
  01文書は `clamp()` を使う大見出し系だけを6段階に整理していたが、本文サイズ以下の固定rem
  （ラベル・キャプション・メタ情報など）はノーマークで、実際には0.66rem〜1remの間に
  11種類の値が存在する。Ant Designが引用済みの「3〜5種に抑えるべき」という原則に、
  01文書が対処した範囲より遥かに大きく違反している。
- 次に信頼度が高いのは **`.work-award` と `.detail-award` の不一致**（第2章）。
  `style.css` 自身のコメントが「カードのバッジと同じミントの帯で揃える」と明言しているのに、
  実装（letter-spacing）が揃っていない。コード自身の意図と実装が矛盾している、根拠が最も強い項目。
- 3番目は **opacityの遷移でイージングが `03_color-motion.md` の既定ルールに反している箇所が2つ**
  ある（第3章）。これも「サイト自身が定めたルール」との矛盾なので信頼度が高い。
- 残りはスペーシングの外れ値（第4章、02文書自体の記述訂正も必要）、確認できず止まりの項目（第5章）、
  細かい点（第6章）。

安全に直せるもの（自信度：高、単一プロパティ変更で副作用が読み切れるもの）から先に着手してよい。
自信度：中／低は、実データ（`works-data.js` の文言量）やスクリーンショットでの確認が先。

## 1. 【最優先・自信度：中〜高】固定remフォントサイズが11段階ある（01文書の対象外）

### 現状

`style.css` 内の `font-size: <数値>rem;`（`clamp()` を使わない固定値）を全数調査すると、
以下の11種類が使われている（出現行）。

| 値 | 出現数 | 使用箇所（セレクタ／行） |
|---|---|---|
| `1rem` | 2 | `body`(79) / `.detail-info-box p`(815) |
| `0.95rem` | 1 | `.site-logo`(253) |
| `0.92rem` | 5 | `.about-meta dd`(593) / `.about-tools li`(599) / `.detail-role`(706) / `.detail-meta dd`(877) / `.ui-image-caption`(928) |
| `0.9rem` | 2 | `.works-note`(358) / `.detail-site-link`(838) |
| `0.85rem` | 2 | `.filter-btn`(373) / `.work-role`(524) |
| `0.8rem` | 1 | `.site-nav a`(265) |
| `0.78rem` | 1 | `.detail-award`(725) |
| `0.75rem` | 2 | `.back-btn`(665) / `.dummy-text`(988) |
| `0.72rem` | 1 | `.detail-meta dt`(869) |
| `0.68rem` | 6 | `.label`(171) / `.work-category`(533) / `.detail-code`(712) / `.detail-info-heading`(807) / `.ui-images-heading`(890) / `.detail-pager-label`(963) |
| `0.66rem` | 2 | `.work-award`(489) / `.work-badge`(542) |

### 根拠

- `research/data/design-systems/ant.txt` 153行目：「フォントスケールは3〜5種類程度に抑えるべき」。
  `01_typography.md` 第3章はこの原則を `clamp()` の大見出し系（9種→6種）にだけ適用しており、
  この固定remの11種類は当時のスコープに入っていなかった（01文書には一切記載がない）。
- `01_typography.md` 冒頭「共通パーツ」の設計意図（`style.css` 165-168行目のコメント）は
  「作品コード・項目名・注釈など『読ませない情報』はすべて `.label` のスタイルに統一する」
  であり、`.label` は `font-size: 0.68rem` と明記されている。にもかかわらず同じ役割の
  `.work-award`・`.work-badge` は `0.66rem`（0.68との差はわずか0.3px相当）を使っている。

### 提案（安全に直せる部分）

- `.work-award`（489行目）と `.work-badge`（542行目）の `font-size: 0.66rem` →
  `font-size: 0.68rem` に統一。差が0.3px相当で視覚的にほぼ知覚できず、レイアウト崩れの
  リスクが最小。**自信度：高。**

### 保留（人間の判断が必要）

- `0.72rem`（`.detail-meta dt`）、`0.75rem`（`.back-btn` / `.dummy-text`）、
  `0.78rem`（`.detail-award`）、`0.8rem`（`.site-nav a`）、`0.85rem`（`.filter-btn` / `.work-role`）、
  `0.9rem`（`.works-note` / `.detail-site-link`）、`0.92rem`（5箇所）を何段階にまとめるかは、
  「ナビ・クリック要素」「メタ情報」「本文よりやや小さい説明文」のどれに属するかを
  実際の画面で確認してから決めたい。**確認できず**（スクリーンショットが必要）。
- `text-transform: uppercase` の有無や `color: var(--ink-mid)` / `var(--ink-weak)` の
  使い分けも一見ばらついているが、`works-data.js` を確認したところ `award`（受賞歴）や
  `role`（担当）の実データは日本語文字列（例：「第22回 ACジャパン広告学生賞 優秀賞」）で、
  `text-transform: uppercase` は和文には効かない。**この差は実装ミスではなく無関係**と判断できる。
  コード改善担当は uppercase の有無を「揃えるべき不整合」としては扱わないこと。

### リスク

- font-sizeを一段階でも変えると、行折り返し位置が変わる可能性がある。特に
  `.detail-award`（受賞歴、日本語の長い文言が入る）は `0.78rem` から下げると
  折り返しが増えるおそれがあり、変更前後でスクリーンショット比較が必須。

## 2. 【自信度：高】`.work-award` と `.detail-award` が「揃える」意図なのに揃っていない

### 現状

| プロパティ | `.work-award`（479-493行目） | `.detail-award`（718-728行目） |
|---|---|---|
| font-size | `0.66rem` | `0.78rem` |
| letter-spacing | `0.08em` | `0.06em` |
| padding | `8px 14px` | `9px 18px` |
| line-height | `1.4` | （指定なし） |
| font-weight / color / background | 500 / `--ink` / `--mint`（共通） | 500 / `--ink` / `--mint`（共通） |

### 根拠

- `style.css` 479行目のコメント：「受賞バッジ。金色をやめ、ミントの小さな帯にした」
- `style.css` 718行目のコメント：「受賞歴。**カードのバッジと同じミントの帯で揃える**」
  → コード自身が「揃える」と明言しているのに、5つのプロパティのうち3つ（letter-spacing /
  padding / font-size）が実際には揃っていない。
- `letter-spacing: 0.06em` は、このサイトの正の字送りの中では `.site-nav a`（267行目）と
  `.filter-btn`（375行目）という**ナビ・クリック要素専用の値**であり、バッジ・ラベル系は
  すべて `0.08em`（`.label` を含む6箇所、第1章参照）。`.detail-award` だけが
  ラベル系なのにナビ系の値を使っており、コピペ由来の取り違えである可能性が高い。

### 提案

- `.detail-award` の `letter-spacing: 0.06em` → `letter-spacing: 0.08em` に修正。
  **自信度：高。** 単一プロパティの微修正で、レイアウトへの影響（折り返し位置）はほぼない。
- `font-size`（`0.66rem` vs `0.78rem`）と `padding`（`8px 14px` vs `9px 18px`）の差は、
  detail-award がページ全体でより大きい文字（h1が`clamp(2rem,5vw,3.4rem)`）の隣に置かれる
  ことを踏まえた**意図的な拡大**の可能性がある。安易に0.66rem/8px 14pxへ統一すると
  detail-award ページ内で相対的に小さすぎて見える恐れがある。**確認できず（要スクリーンショット）
  ＝人間の判断が必要。**

### リスク

- letter-spacing変更は低リスク。font-size/paddingの統一は、detail-award側を縮小すると
  ヒーローエリアでバッジが埋もれて見える可能性があり、逆にwork-award側を拡大するとカード内で
  他要素とのバランスが崩れる可能性がある。

## 3. 【自信度：高】opacityの遷移で `03_color-motion.md` のイージングルールに反する箇所が2つ

### 現状

`03_color-motion.md` 第3章の既定ルール：

> 移動・拡大縮小・フェード（`transform` / `opacity`）→ `var(--ease-out)`
> 色の切り替え（`background-color` / `border-color` / `color`）→ `ease`（標準）

このルールに沿っているopacity遷移（正しい例）：
`.work-hover-overlay`（453行目 `opacity 0.4s var(--ease-out)`）、
`.fade-on-scroll`（1031行目 `opacity 0.5s var(--ease-out)`）。

一方、次の2箇所は **opacityなのに `ease`（標準）のまま**になっている。

| セレクタ／行 | 現在の値 | 提案する値 |
|---|---|---|
| `.detail-pager-link`（950行目） | `transition: opacity 0.3s ease;` | `transition: opacity 0.3s var(--ease-out);` |
| `#splash-screen`（1006行目） | `transition: opacity 0.9s ease, visibility 0.9s ease;` | `transition: opacity 0.9s var(--ease-out), visibility 0.9s ease;` |

（`visibility` 側の `ease` はそのままでよい。`visibility` は中間値を持たない離散プロパティで、
どのイージング関数を指定しても見た目には影響しないため、色系のルールに従うかどうかを
議論する対象にならない。）

### 根拠

- `03_color-motion.md` 104-111行目で明文化された、このサイト自身のルール。
- サイト内の他のopacity遷移（`.work-hover-overlay`・`.fade-on-scroll`）は全て
  `var(--ease-out)` を使っており、この2箇所だけが例外になっている。

### リスク

- 非常に低い。`ease` と `cubic-bezier(0.16, 1, 0.3, 1)` はどちらも「滑らかに減速する」系の
  カーブで、視覚的な違いはごくわずか。`.detail-pager-link` は前後作品リンクのホバー時の
  減光、`#splash-screen` はスプラッシュ画面のフェードアウトで、どちらもクリティカルな
  演出ではない。**自信度：高。**

## 5. 【自信度：低・保留】`.contact-email` のclamp外れ値（学習①からの持ち越し）

`style.css` 610行目 `.contact-email { font-size: clamp(1.4rem, 5vw, 3.4rem); }` は、
最大値 `3.4rem` は `--fs-h1`（`clamp(2rem, 5vw, 3.4rem)`、700行目）と同じだが、
最小値だけ `1.4rem` と低い。

学習①では「意図的な差か作業中のブレか判別できない」として保留にしていた。今回、
用途を見直すと：`.contact-email` はメールアドレスという**長い英数字文字列**を表示する要素で
（634行目付近のHTML参照）、`word-break: break-all` が指定されている（613行目）。
最小画面幅でメールアドレスが `--fs-h1` 相当（最小2rem）の大きさだと折り返しが増えて
縦に間延びする可能性があるため、**最小値だけ低く設定するのは意図的な配慮である可能性が高い**、
という仮説をここに記録する。

ただし実際の画面でどう見えるかを確認していないため、**結論はまだ「確認できず」のまま**とする。
2本目でもコードを変更しない縛りのため、次のコード改善担当は「触らない」を既定にしつつ、
もし変更するとしても最小画面幅でのメールアドレス表示を実機・スクリーンショットで
必ず確認してから判断すること。

## 手を出してはいけないもの（再掲・重要）

次の3点は、次のコード改善担当がこの指示書を見てもCSS変更の対象にしないこと。

1. **`works-data.js` の文言**（`summary` / `description` / `caption` など） —
   本人が自分の言葉で書く領分。デザインシステムの適合・不適合の対象外。
2. **レイアウトの大きな作り直し** — 本人との対談で決めた構成（2カラムのHero、
   作品カードグリッドの列数など）。本書で指摘した内容はすべて「値の微調整」の範囲に収まり、
   構造を変える提案は一つもしていない。
3. **ロゴの「!」のミント色**（`.mark { color: var(--mint); }`、199-201行目） —
   `03_color-motion.md` 第1章のコントラスト制約の例外として、ロゴタイプの一部だから
   意図的に許容されている。本文の可読性ルールとは無関係なので、コントラスト比を理由に
   ここを変更対象に含めないこと。
