# 03. 色・モーション

根拠は `research/data/reference-sites.json` の `colors_hex` / `cubic_bezier` と、
`research/data/design-systems/ant.txt`（Ant Designのコントラスト基準・配色原則）。
Carbon / デジタル庁 / Polaris のテキストにはモーション・配色の数値記載がなかったため今回は使っていない。

---

## 1. ミント緑のコントラスト制約（最重要・必読）

**`#1decaa`（ミント）は白背景 `#ffffff` に対してコントラスト比 `1.54:1` しかなく、
WCAG AAの基準（通常文字4.5:1以上、大きな文字でも3:1以上）を満たさない。**

→ **ミント緑を文字色として使ってはいけない。** リンクの下線色、アイコンの塗り、
装飾的な罫線・アンダーラインなど「文字そのものの色ではない」用途に限定する。

一方、**ミントを背景色にして黒文字（`--ink: #0d0d0d`）を乗せた場合はコントラスト比 `12.62:1` と
非常に良好**なので、ボタンの背景やタグ・バッジの背景など「面としてミントを使い、その上に
黒文字を乗せる」構成であれば問題なく使える。

**このサイトのルール：**

| 用途 | 可否 |
|---|---|
| 白背景の上の文字色としてミントを使う | ❌ 禁止（コントラスト不足） |
| ミントを背景にして黒文字を乗せる（ボタン・バッジ等） | ✅ 可（12.62:1） |
| アイコンの塗り・下線・罫線・グラデーションの一部 | ✅ 可（文字の可読性に関与しないため） |
| フォーカスリング（`a:focus-visible` 等） | ✅ 現状どおり可（線であって文字色ではない） |

`style.css` 119-123行目の `outline: 2px solid var(--mint)` はこの分類上「線」なので問題なし。
ミントを本文リンクの文字色に転用するような変更は今後NGとして明文化する。

## 2. 色の役割分担

`style.css` の `:root`（33-44行目）で定義済みの変数をベースに、役割を再整理する。

| 変数 | 値 | 役割 |
|---|---|---|
| `--bg` | `#ffffff` | 基本背景 |
| `--bg-sub` | `#f6f6f6` | わずかに沈めた背景（区画分け用） |
| `--ink` | `#0d0d0d` | 本文・見出しの文字色（純黒ではなく少し柔らげてある） |
| `--ink-mid` | `#6e6e6e` | 二次的なテキスト（キャプション等） |
| `--ink-weak` | `#a5a5a5` | 三次的なテキスト（プレースホルダ・非活性） |
| `--line` | `#e4e4e4` | 罫線（区切り線） |
| `--mint` | `#1decaa` | アクセント（1章の制約に従う） |
| `--pink` | `#eb2b98` | グラデーション専用（署名グラデーションの片端。単独使用は現状なし） |

### 根拠：グレースケール3段階（強・中・弱）は参考サイトでも共通パターン

- **ds-k**：`141414`(13回) / `585858`(6回) / `b0b0b0`(6回) / `d9d9d9`(20回) / `f4f4f4`(5回) の
  5段階グレースケールを保持。
- **109ichiki**：`a4a4a4`(1) / `565656`(1) と2段階の中間グレーを保持。
- **komeinc**：`8a8a8a`(23回)を二次テキストとして多用。
- **unium**：`94969d`(19回)を中間グレーとして使用。

→ 「濃い本文色＋1〜2段階のグレー」で文字の優先度を表す構造はほぼ全サイト共通。
このサイトの `--ink` / `--ink-mid` / `--ink-weak` の3段階構成はこの傾向と一致しており
**変更不要**。

### 根拠：アクセントカラーは1色に絞り、使用比率を抑える

- **arkreis**：ベース `000`(29回)・`fff`(28回)に対し、アクセント `3cdc3c`(緑, 11回)のみ。
  グレースケール以外の色を1色に絞っている点がこのサイトの「ミント1色」方針と最も近い。
- **komeinc**：ベース色に対しアクセント `0000b9`(紺, 78回)を高頻度で使用しており、
  アクセントというより準ベース色に近い扱い。このサイトの「ミントは絞って使う」方針とは異なる例。
- **zeroten**：`5985d1`(青)・`fd4690`(ピンク)・`fecab5`(肌色)・`62c3ff`(水色)を
  各5回ずつ均等に使うマルチカラー構成。イラスト要素の彩色に使われていると推定され、
  UIのアクセントカラー設計としては参考にならない。

→ 6サイトの中でアクセントの使い方は「1色を薄く使う」（arkreis型）と
「1色を濃く多用する」（komeinc型）に分かれる。このサイトの方針（ミント1色・グラデーションは
スクロールバーのみ）は **arkreis型**。すでにこの方針で作られているため**変更不要**、
ただし「ミントを濃く多用する」komeinc型への変更は今後も採用しない、と明文化しておく。

## 3. イージング（cubic-bezier）

### 実測とこのサイトの `--ease-out` の検証

`style.css` 53-55行目のコメントには「6サイトともx1が小さく(0.09〜0.22)y2が1のease-out系で
共通していた」とあるが、`reference-sites.json` の全カーブを突き合わせると**この記述はやや
言い過ぎ**であることが分かった。各サイトの最頻カーブ（＝そのサイトの基調）で見ると：

| サイト | 最頻カーブ | 出現数 | 「x1小・y2=1」に該当するか |
|---|---|---|---|
| ds-k | `cubic-bezier(.09,1,.36,1)` | 63 | ○ |
| komeinc | `cubic-bezier(0.215,0.61,0.355,1)` | 93 | ○（x1=.215で境界寄り） |
| zeroten | `cubic-bezier(.165,.84,.44,1)` | 29 | ○ |
| 109ichiki | `cubic-bezier(.16,1,.3,1)` / `cubic-bezier(.22,1,.36,1)` | 各1（同数） | ○ |
| **arkreis** | `cubic-bezier(.785,.135,.15,.86)`（これ1種類のみ） | 5 | **×**（x1が大きくy2も1未満。ease-in-out寄り） |
| **unium** | `cubic-bezier(0.4,1.07,1,1)` | 62 | **×**（y1が1を超えるオーバーシュート＝バウンド系） |

→ 「x1小・y2=1」の傾向を主要カーブとして持つのは6サイト中4サイト（ds-k, komeinc, zeroten,
109ichiki）で、arkreisとuniumは異なる傾向（ease-in-out系／オーバーシュート系）を持つ。
**「6サイトとも」という既存コメントの表現は事実と完全には一致しない**ため、これは是正事項として
`_log_01.md` に記録した（`style.css` 自体は今回変更しない）。

一方、このサイトの `--ease-out: cubic-bezier(0.16, 1, 0.3, 1)` は **109ichiki の実測値と
完全一致**しており、かつ多数派（4/6）の傾向とも整合する。**採用を継続してよい。**

**このサイトのルール：**

| 用途 | イージング |
|---|---|
| 移動・拡大縮小・フェード（transform / opacity） | `var(--ease-out)` = `cubic-bezier(0.16, 1, 0.3, 1)` |
| 色の切り替え（background-color / border-color / color） | `ease`（標準） |

この使い分けはすでに `style.css` の実装（243, 283, 378行目など）で一貫しており、変更不要。

## 4. duration（長さ）

実測（`style.css` の `transition`、13箇所）：

| 用途 | 秒数 |
|---|---|
| 色の切り替え（hover等） | `0.3s`〜`0.4s` |
| 要素の移動・フェード（ボタン等、小さい要素） | `0.4s` |
| 大きい要素の移動（画像の拡大など） | `0.5s`〜`0.6s` |
| 全画面演出（スプラッシュ画面のフェードアウト） | `0.9s` |

→ 「要素が大きい・画面全体に関わるほど長くする」という傾向が既存コードから読み取れる。
これを明文のルールとして固定する：

> **色の切り替えは0.3〜0.4s・ease。要素の動き（transform/opacity）は0.4〜0.6s・`var(--ease-out)`で、
> 対象が大きいほど長い方（0.6s側）に寄せる。画面全体を覆う演出（スプラッシュ等）は0.9s前後まで
> 許容する。** これより長いdurationは基本的に使わない。

参考6サイトのCSSからは`transition-duration`の値が正規表現の集計項目に含まれておらず、
数値としての裏付けは取れなかった。**この章のduration表は `style.css` の実装からの帰納であり、
参考サイトのデータによる裏付けではない点に注意（確認できず＝外部データでの検証はできていない）。**
